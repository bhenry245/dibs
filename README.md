**Split the bill at the table.** Snap the receipt, share a QR code, everyone calls dibs on what they ordered, and Dibs chases the payments so you don't have to.

> 🚧 **In development.** The foundation is in place; the bill-splitting features are being built now. See [Status](#status).

## How it works

1. The **Captain** pays the bill and photographs the receipt.
2. AI reads the receipt into line items, tax and tip.
3. Dibs shows a **QR code**. The **Crew** scan it and claim what they ordered. No account or app install needed.
4. Everyone sees exactly what they owe, including their share of tax and tip, with one-tap Venmo / Cash App / Zelle links.
5. Dibs sends reminders until the Captain confirms they've been paid.

Dibs never handles money. It only tracks who owes what.

The full design (data model, money math, architecture, security) is in [docs/design.md](docs/design.md).

## Running locally

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) (runs Postgres)
- [uv](https://docs.astral.sh/uv/getting-started/installation/) (installs the pinned Python and backend packages)
- [nvm](https://github.com/nvm-sh/nvm#installing-and-updating) (installs the pinned Node version)

You don't need to install Python, Node or Postgres yourself: the versions are pinned in the repo (`.python-version`, `.nvmrc`, `docker-compose.yml`) and the tools above fetch them.

### First-time setup

```bash
# Database: Postgres 17 on localhost:5433
docker compose up -d

# Backend: install packages and create the tables
cd backend
uv sync
uv run alembic upgrade head

# Frontend: install the pinned Node, then packages
cd ../frontend
nvm install
npm ci
```

### Start the app

Run each in its own terminal:

```bash
# API on http://localhost:8000 (docs at /docs)
cd backend && uv run fastapi dev src/dibs/main.py

# Web app on http://localhost:5173
cd frontend && npm run dev
```

Open http://localhost:5173. A green **API connected** dot means the frontend, API and proxy are all wired up.

> **Why port 5433?** It avoids clashing with a Postgres already installed on the host's default 5432. To point the backend somewhere else, set `DATABASE_URL`.

### Tests and checks

These are the same commands CI runs:

```bash
# Backend
cd backend
uv run ruff check . && uv run ruff format --check .
uv run pytest

# Frontend
cd frontend
npm run lint
npm run build   # type-checks, then builds
npm test
```

### Database migrations

The schema is managed by Alembic; migration files in `backend/alembic/versions/` are the source of truth.

```bash
cd backend
uv run alembic revision --autogenerate -m "describe the change"   # after editing models.py
uv run alembic upgrade head                                       # apply
uv run alembic downgrade -1                                       # undo the last one
```

Always read an autogenerated migration before applying it.
